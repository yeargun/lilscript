## Distilled

- New family `lil2-<library>` (new folders, GitHub repos, Pages); the existing `*lil` ports stay as they are.
- Typed by design, so compiled output is flat (primitives and arrays, no per-item objects); the pluggable
  parts (syntax extensions, tree transforms, renderers) get a designed typed plugin model.
- Behaviour must equal upstream: same markdown in, same HTML / React output. The API may change, and the
  tests are cloned and rewritten for the new API.
- Built bottom to top, one submodule at a time, ending in `lil2-react-markdown`. React version matters little.
- Final comparison: lil2-react-markdown vs react-markdown vs react-markdownlil, and each submodule likewise —
  bundle size (raw/gzip/Brotli) and performance.

### Distilled

- Load time must not regress either (Chromium load was +1.5 ms): find the cause and design it away.
- Every id and every enum is an integer by design (tag names, property names, plugin and construct selection,
  alignment, reference kinds, identifiers); strings exist only as output content or at the final DOM/React
  boundary. No string enums anywhere.
- Robust, elegant, performant — no glue layers. The design may change freely as long as the result is faster,
  smaller, properly typed, and behaves (and looks to the user) exactly like upstream.
