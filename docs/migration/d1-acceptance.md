# D1 delivery formats and manifests

D1 follows Q4 (`a3b55dab`) and is complete under the contract below. D2 follows.

1. Implement CJS, library IIFE/UMD and explicit classic bare delivery through the
   same planned, named and scored output. Keep live exports/imports, unbound calls,
   source strictness, lexical activation, host dependencies and cycle ordering.
2. Register TOML publication/interoperability controls, policy identity, cloning
   and resource ownership. Defaults and consumer/byte/runtime tradeoffs are explicit.
3. Repair manifest module labels, injective `[path]` filenames/URL spelling,
   stale v2 cleanup and precise `bundle.cost` leaf diagnostics. Case tooling can
   exercise CJS and bare lanes. Every delivered file keeps its exact scored bytes.
4. Qualify the coherent batch with focused independent runtime oracles, CLI
   manifests and separate raw/gzip/Brotli production artifacts. Record the limits,
   update index/history, commit and push. Continue D2 immediately.

D2 retains lazy side-effect/cycle placement, consumer shakeability, host-module
integration, source maps and Q4's public stored-product graph adapter. D3 owns
shared graph consumers and compiler-written port/package entry integration.

The delivered containers preserve live namespace getters, live import reads,
unbound imported calls, strict module functions and lexical host arguments.
CommonJS includes split/preserved/lazy files; browser containers are single files
per entry. Bare remains an explicit application script. Namespace templates and
foreign globals have checked spellings; interop/default-export behavior is explicit.
Each file is parsed in its actual frame and its emitted program statements are
compared to an independent target-tree digest. Generated linkage and wrappers are
covered by consumer oracles, not claimed as a whole-wrapper structural proof.

records focused tests, independent release consumers, all three actual codec
measurements and exact manifest receipts. No library/fleet rerun. The final
