Future direction / 2026

Smaller by proof, not patches.

LilScript will get smaller by making more compact programs legally reachable, then measuring complete compiler output with the codec that will actually serve it. Not by adding a minifier after the compiler. Not by recognizing package names. Not by assuming every getter is pure.

Current truth The architecture work improved correctness and decision visibility, but current Motion, Marked, MobX, and jQuery size results are mixed. The next phase begins by recovering legal incumbents, not declaring a win.

The objective

For every declared supported and semantically equivalent maintained boundary, size-first LilScript should eventually be no larger than the best eligible pinned JavaScript toolchain for the selected metric.

01 / mechanism

How the bytes come out.

The compiler's advantage is upstream of minification. Types and boundaries define which programs are equivalent; exact codec scoring chooses among them.

A

Freeze the contract

Semantics, source intent, public ABI, host names, and unsafe assumptions.

B

Prove legality

Ownership, escape, effects, identity, ranges, aliases, captures, property hooks.

C

Expose choices

Retain the incumbent; register every admitted legal representation and rejection.

D

Validate output

Bindings, properties, syntax floor, ABI, module links, and source obligations.

E

Score the whole

Exact raw, gzip, or Brotli bytes for one complete artifact or declared artifact set.

02 / levers

Six places we expect to remove bytes.

Each lever must expose a generic proof and an explicit alternative. If it works only for one package-shaped AST, it does not belong in the compiler.

01 / recover

Keep old legal winners reachable.

Serialize and replay the complete selected recipe. When a new compiler regresses, identify the first unreachable or outranked choice instead of guessing from a raw diff.

02 / dissolve

Delete representations before naming them.

Prove when structs, classes, closure environments, arrays, and owned objects can disappear into SSA. Keep-object remains a scored competitor, because dissolution is legal, not automatically smaller.

03 / language

Replace dynamic glue with reusable proofs.

Typed optional bags, host-callable methods, accessors, object spread, stronger array facts, and hook-free owned data can remove adapters and string keys without lying about Proxy or getter behavior.

04 / placement

Move values, not just punctuation.

Effect-safe producer sinking, control-flow representation, call-graph sharing, closure placement, and declaration order can remove temporary stores and expose repetition that local peepholes miss.

05 / target

Carry identity into JavaScript.

A narrow hygienic target tree will preserve binding, property, call, allocation, effect, ABI, and lowering identities. It replaces expensive guesswork over generated strings, family by family.

06 / search

Spend codec work where choices interact.

Cover every admitted family once, then coordinate measured interactions. Use cheap predictors to schedule. Use the selected exact codec to accept. Add entity-scoped choices only when global switches demonstrably lose.

03 / heuristics

Heuristics schedule. They do not decide.

Compression is non-additive and the legal search space is combinatorial. The practical design is a bounded portfolio with hard semantic gates.

Technique Allowed job Failure control
Raw delta Order cheap proposals and reject obvious duplicates. Never select a gzip/Brotli winner from raw size alone.
Codec predictor Prioritize candidates likely to improve the selected metric. Version and calibrate it; exact final scoring remains authoritative.
Coverage first Give each admitted representation, call-graph, control, naming, and pooling family work. Report unvisited and starved families instead of calling the incumbent best.
Joint family Explore a measured non-monotone interaction such as spelling plus naming. No general cross-product. Keep the incumbent in the joint set.
Entity scope Let different functions or allocations choose differently when evidence shows mixed winners. Do not add per-entity machinery before a global option is proven insufficient.
Deep release search Spend a larger explicit budget on reproducible release candidates. Compile-time and memory SLOs remain visible; more search is not automatically better.
04 / guardrails

Smaller is valid only after correct.

Hard constraints

  • Language evaluation, exceptions, coercions, identity, and effects.
  • Live source intent such as an explicit value | 0.
  • Expected public ABI and observed emitted ABI.
  • Exact browser/host names and declared unsafe assumptions.
  • Binding, property, module, target-syntax, and allocation identity.
  • Independent behavior and API suites for the claimed boundary.

Things we refuse

  • Post-minifying compiler output to manufacture a compiler win.
  • Package-name, path, or library-shaped optimization matchers.
  • Default-on pure-getter or pristine-host assumptions.
  • Objective-dependent exports, descriptors, or constructibility.
  • A universal solver, proof database, or full JS frontend without measured need.
  • Calling bounded search globally optimal.
05 / pressure ports

Four libraries, four different lessons.

Libraries are pressure tests, never compiler matchers. Every boundary needs its own behavior gate, shipping artifact, and eligible baseline.

mixed regression

MotionLil

Large surfaces regress while a tiny import improves.

  • Measure each import boundary independently.
  • Audit optional/keyframe JsValue bags.
  • Preserve the real DOM API and tree-shaking boundary.
small Brotli regression

MarkedLil

Behavior is green; the selected package artifact must recover its prior recipe.

  • Keep public options exact.
  • Separate public, parse-only, and closed-key rows.
  • Use ownership proof only for compiler-owned data.
split result

MobXLil

Regular output improves slightly; production-min regresses materially.

  • Replay production-only decisions.
  • Keep Proxy, Reflect, accessors, and descriptors exact.
  • Move class/accessor tables only with proof.
unchanged, still larger

jQueryLil

The remaining gap is not solved by more naming or a post-minifier.

  • Improve effect-safe value placement.
  • Widen sound array-ness facts.
  • Use landed ordinary-object and expression forms.
06 / execution

The order matters.

Evidence and legality come before new search machinery. Measured loss recovery comes before speculative architecture.

Phase 0

Replayable evidence

Fingerprint every source, config, artifact, scorer, harness, recipe, and baseline. Split compiler-output from deployment lanes.

Phase 0.5

Legality and ABI

Separate world, format, and public roots. Compare expected ABI with observed final artifacts before scoring.

Phase 1

Recover incumbents

Replay old legal winners and identify the first unreachable or outranked decision for each regression.

Phase 2

Consolidate decisions

Make the registry own recipes and route candidates through one validation/scoring primitive without adding new alternatives.

Phase 3

Hygienic target JS

Move identity-sensitive generated-text work into a narrow target representation, one measured family at a time.

Phases 4-5

Reusable proofs, then smarter search

Close library gaps with language facts. Add joint/entity search only after evidence shows the existing model misses a legal win.

Phase 6

Delete and certify

Remove superseded text and policy paths only after behavior, size, resource, and evidence gates pass.

The release proof

A win is a conjunction.

No aggregate average, historical screenshot, or cross-metric trade can substitute for the exact boundary under test. 

supported boundary
AND semantics + API + ABI pass
AND direct LilScript compiler artifact
AND eligible independent JavaScript baseline
AND selected metric uses the pinned codec
AND lilscript_bytes <= best_baseline_bytes
AND compile/runtime costs are reported
