LilScript, Terser, and Oxc are not the same machine

Terser and Oxc take JavaScript and emit smaller JavaScript. LilScript compiles a typed language, rewrites the program, then searches among equivalent JS spellings by measuring the finished file under gzip or Brotli. That is the architecture difference. Everything else is detail.

The category error

Calling all three “minifiers” hides the only fact that matters for architecture. Terser and Oxc are JavaScript-to-JavaScript compressors. They must preserve the observable shape of an open JS program: getters, eval, reflection, prototype mutation, export names, Function.prototype.name, and string-keyed properties. LilScript is a language compiler. Its input is not JavaScript. Types, effects, escape, and a closed module graph exist before any JS is spelled.

A JS minifier shrinks a spelling. LilScript is allowed to change the app — dissolve a class into SSA scalars, erase a field because it is an index not a key, then pick names and layout because they compress, not because they are short.

Oxc-the-project is larger than a minifier (parser, linter, transformer, formatter). In this comparison “Oxc” means the minifier crate, which is also what Vite 8 / Rolldown use after the bundler has already tree-shaken and chunked. Terser is only a minifier. LilScript owns frontend, optimizer, emitter, codec scoring, and a second C/native backend of the same IR.

Overall architecture

Read the three pipelines as factories with different inputs, different IRs, and different judges. Stages are sequential unless noted.

Language compiler · Rust

LilScript

Typed modules → CFG/SSA → many legal JS programs → keep the one the codec likes. Optional C from the same IR.

  1. 01Discover & parse .lil (own grammar, never JS)
  2. 02Link the static graph; private names get one identity
  3. 03Type, effect, and narrowing analysis
  4. 04Lower to typed control-flow IR; promote locals to SSA
  5. 05Optimize: fold, CSE, specialize, inline, scalar-replace, DCE, compress passes
  6. 06Level-1 search: clone IR, vary optimizer policy, emit configured JS, score
  7. 07Level-2 search: beam over spelling, pooling, layout, alphabets
  8. 08Optional parsed JS peephole, still codec-scored
  9. 09Rank by cost_model (raw / gzip-9 / Brotli-11). Startup guard can reject
  10. 10Native path: clone IR, different options, emit C / exec

IR: typed SSA CFG (src/ir.rs)
Emit: codegen_ir_js.rs
Judge: complete-artifact codec, not character count

JS minifier · JavaScript · Uglify-ES fork

Terser

Parse JS into a mutable AST, squeeze it with named compress options, rename, print. One program in, one program out.

  1. 01parse() → Terser AST (AST_Toplevel)
  2. 02Optional wrap / enclose / global_defs
  3. 03figure_out_scope — SymbolDef, eval/with, enclosed names
  4. 04Compressor is a TreeTransformer. Walk every node; apply the compress catalog
  5. 05Repeat for compress.passes (default 1; quality setups use 2–3)
  6. 06Re-scope. compute_char_frequency so short names use common letters
  7. 07mangle_names (base-54). Optional mangle.properties (off; often unsafe)
  8. 08OutputStream prints compact JS + source map

IR: mutable JS AST + scope maps
Loop: local rewrites until pass budget
Judge: printed UTF-8 length. Gzip is a side effect of frequency-weighted names, not an objective.

JS/TS minifier · Rust · Vite 8 default

Oxc minifier

Arena AST, one semantic model, normalize, peephole to a bounded fixpoint, slot-based mangler, codegen. Built to be fast and correct on test262.

  1. 01oxc_parser into an arena-allocated AST
  2. 02SemanticBuilder — scopes, symbols, references
  3. 03Normalize — while→for, const→let, drop useless 'use strict'
  4. 04Compressor runs PeepholeOptimizations until the AST stops changing, or ~10 iterations
  5. 05Incremental scoping: dropped nodes prune references; no full rebuild each pass
  6. 06oxc_mangler — liveness slots, reuse non-interfering symbols, frequency rank, base-54/64
  7. 07Equal-length names shuffled by declaration order (Closure’s gzip trick)
  8. 08oxc_codegen compact print. In Vite, this runs after Rolldown tree-shake & chunks

IR: arena JS AST + oxc_semantic
Loop: 17+ peephole families to fixpoint
Judge: printed length. Gzip-aware mangling, still no Brotli measurement.

How deep each optimizer sits

Same delivery problem, different stacks. Minifiers never see the layers LilScript spends most of its compile on.

What each optimizer is allowed to believe

Architecture is a permission structure. The interesting transforms are illegal on open JavaScript and routine on typed LilScript.

LilScript optimizer, in order

Production compilation never emits from the AST. After lowering, optimize_control_flow is a closed-world SSA pipeline. Search may clone this IR and turn families off; it may not skip type checking or invent compression tactics absent from config.

  1. Internalize entry globals; drop unread globals.
  2. mem2reg (skip exception-region and mutable-capture locals).
  3. Fuse linear array / object builders.
  4. Scalar fixed point: constant fold, finite-value propagation, algebraic simplify, CSE, unreachable.
  5. Immutable global prop; devirtualize methods and known closures.
  6. Specialize constant parameters and profiled call sites; clone constant-capture closures.
  7. Inlining fixed point interleaved with DCE (size, CFG, and growth limits).
  8. Escape analysis; scalar-replace classes and aggregates; dead field stores.
  9. Compress passes: path-sensitive constants, expression superopt, partial-escape sinking, array-pipeline fusion. Region outlining is default-off because helpers often win raw and lose Brotli.
  10. Second inlining wave; parameterized / identical private-function merge; final DCE and tree-shake; prune unused foreign imports.

Then JavaScript is not “printed.” IrJsOptions chooses spelling: arrow vs function, !0 vs true, string pooling, identifier alphabet, function layout (source / similarity / codec window), phi destruction, comma expressions, and so on. Candidate search mutates those options and re-emits the whole file.

Both minifiers are peephole machines on a JS AST. The catalogs overlap; the implementations and pass order do not. Terser’s strength is a decade of interacting options. Oxc’s is speed plus a Closure-flavored mangler, sitting behind a modern bundler.

What “smaller” means

Terser and Oxc optimize a proxy: fewer characters in the printed file. That usually helps gzip and Brotli, and sometimes does not. LilScript treats the proxy as untrustworthy and measures the artifact the network actually sends.

Fixpoint vs two-level search

Terser and Oxc run one program to a local fixed point: apply every legal peephole until nothing changes (or passes run out). LilScript keeps the configured pipeline as a mandatory candidate, then spends a budget exploring other complete programs.

What search is for

Raw, gzip, and Brotli disagree. Function layout inside a 32 KiB DEFLATE window is a different problem from Brotli’s 4 MiB history. Identifier alphabets that match the file’s existing letters compress better than a fresh abcdef… sequence. None of that is visible to an AST walker that only asks “is this node shorter?”

What search is not

Not a global optimum — budgets truncate the beam. Not a substitute for types. Not enabled per chunk in split builds (those score chunk plans). Not allowed to turn on a tactic the compression allowlist omitted. The configured baseline always remains a legal output, so an experimental clone cannot make a valid project uncompilable.

Pros and cons

LilScript

  • Changes the program when proofs allow: scalar replacement, field erasure, typed DCE, specialization, function sharing.
  • Optimizes served bytes by measuring gzip/Brotli of complete artifacts, including naming and declaration order.
  • Closed-world ABI is config, not convention: public exports vs internal layout vs extern host names.
  • Native IR keeps JS tricks honest — a size win that would mean something else in C is rejected.
  • On many rewritten libraries this repo publishes, Brotli is substantially under Vite/Oxc (Solid, Motion, marked, monaco cores, etc.).
  • Not a JS minifier. You rewrite the library. That is the product and the cost.
  • Slow when it is trying. Quality-11 Brotli over hundreds of candidates is a release compiler, not a save-hook.
  • Does not always win the same-API fight. Ported jQuery is still behind official jquery.min.js / Terser on Brotli as of the current compression-goal notes.
  • Ecosystem, IDE, and interop are a language’s problems. JsValue holes collapse back to minifier-level conservatism.
  • Split/preserve-modules skip the full emission beam unless joint chunk search is on.

Terser

  • Drop-in on any JS already bundled or concatenated. No rewrite, no types.
  • Best-known JS compress catalog. The interacting pass set still finds bytes Oxc and LilScript-as-a-printer miss on raw JS.
  • Huge option surface: pure_funcs, property mangle + name cache, toplevel, ecma, source maps, IE/Safari workarounds.
  • Battle-tested on the entire npm graph for a decade. Surprising JS is its native habitat.
  • On the same JavaScript text, it is often the size champion (jQuery official min, many single-file libraries).
  • Cannot prove what LilScript proves. Objects, exports, and string keys mostly survive.
  • Optimizes the wrong proxy when gzip/Brotli disagree with character count.
  • Slow (interpreted JS, recursive transformer, multi-pass). Fine for CI, painful in the inner loop of a huge app.
  • Property mangling is a footgun; unsafe modes change semantics.
  • Not a bundler. Comparing Terser-on-a-file to Vite-on-an-app is a methodology error.

Oxc

  • Fast. Arena AST, Rust, incremental scoping. The reason Vite 8 made it the client default.
  • Correctness posture: test262 / Babel / TS suites, conservative effects, no “minify until it breaks.”
  • One toolchain: parser, transformer, linter, formatter, minifier share the AST. Vite/Rolldown already built the graph.
  • Mangler is closer to Closure than Terser’s: liveness slots, name reuse, gzip-oriented equal-length shuffle.
  • A different rewrite mix than Terser — sometimes smaller, often close, always cheaper to run.
  • Same open-JS ceiling as Terser. It will not dissolve your class or mangle a framework property it cannot prove is local.
  • Younger catalog. On stubborn files Terser with passes=3 still wins size.
  • Still judges by print length. Gzip tricks in the mangler; no Brotli-11 competition among equivalent spellings.
  • Standalone minify without Rolldown does not tree-shake a module graph. “Oxc vs LilScript” numbers that include Vite are bundler+minifier vs language+compiler.
  • Unsafe / assumption flags exist; turning them on to chase a baseline is the same trap as Terser unsafe.

When to use which

Ship existing JavaScript

Use Oxc if you are on Vite 8 / Rolldown and you care about build time. Use Terser with module/toplevel and a few passes when the artifact is size-critical and compile time is CI. Do not enable property mangling or unsafe unless the contract proves it. Neither tool replaces a bundler.

Beat those tools on transfer size

You need a different program, not a better printer. LilScript is the bet that types-as-compilation-model plus codec search is that program. It pays when you control the source and can keep host boundaries explicit. It does not pay as a last-mile minifier of code you will not rewrite.

The architectural summary in one line: Terser is the deep JS peephole, Oxc is the fast JS peephole in a modern toolchain, LilScript is a compiler that treats JavaScript as a representation to be searched under a real compressor.
