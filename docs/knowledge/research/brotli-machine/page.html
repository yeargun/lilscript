01 — orientation

The shape of a stream

Brotli is LZ77 plus prefix codes plus a dictionary that both sides already have. A compressed stream is a window size, then a run of meta-blocks. Each meta-block carries its own complete set of prefix codes and then a run of commands. One command says: copy this many literal bytes out of the stream, then copy this many bytes from that far back. That is the entire machine. Everything else is a way to spend fewer bits saying it.

Three things make Brotli different from DEFLATE, and all three cost header bits to set up and pay for themselves in the command stream:

  • A last-distance cache. The four most recent distances get four-bit names, and a whole class of commands reuses the last distance without naming it at all.
  • Context modelling. Literals are coded with a prefix code chosen by the two preceding bytes, so e after th is cheap and e after ( is not.
  • A shared static dictionary. 13,504 words, plus 121 transforms that wrap, cut and capitalise them — reachable as a back-reference past the start of the stream, so the first <div class="container"> in a file can already be a copy.

How to read this page

Every number below is computed live. The decoder was checked against streams from the real Brotli library at five quality levels and four window sizes, and it decompresses Brotli's own compressed copy of its dictionary. The encoder's output is fed back to the real library in the build, which is the only test that counts.

03 — entropy coding

Prefix codes, and the code that codes them

Brotli's prefix codes are canonical, exactly as DEFLATE's are: sort the symbols by (code length, symbol value), hand out codes in increasing order within each length, and the table is fully described by one length per symbol. Lengths are capped at 15.

Bits go into the stream least-significant first, but a prefix code's bits are written reversed, so a decoder reading LSB-first receives them most-significant-bit-first and can walk the tree one bit at a time. That single convention is why the hex dump below never lines up with anything.

Two ways to write a code

A meta-block header spells out every prefix code it uses, in one of two forms:

  • Simple — up to four symbols, listed literally, with lengths fixed by the count (1; 1,1; 1,2,2; 2,2,2,2 or 1,2,3,3). A code with one symbol costs zero bits per use.
  • Complex — the sequence of code lengths, itself prefix-coded by an 18-symbol code-length code, whose own lengths arrive in a fixed order () under a hard-wired 2-to-4-bit code. Symbol 17 repeats zeros, symbol 16 repeats the previous length, and both chain: a second 17 multiplies the pending run by eight.

Both sides stop reading code lengths the instant the code is complete — the Kraft sum reaches exactly 1 — which is a detail an encoder gets wrong once and only once.

04 — framing

The meta-block header, field by field

The stream opens with WBITS, a variable-length code for the window size: one zero bit means 16, otherwise three more bits give 17–24, with a further escape for 10–17. The window is 2^WBITS − 16 bytes; the sixteen missing bytes are what make room for the short distance codes.

Then meta-blocks, each self-contained:

  • ISLAST, and if set, ISLASTEMPTY — an empty stream is two bits.
  • MNIBBLES then MLEN: the uncompressed size, 4, 5 or 6 nibbles, minus one. The escape value marks a metadata meta-block, skipped bytes that never reach the output.
  • ISUNCOMPRESSED (non-final blocks only): pad to a byte and store raw.
  • Block-type machinery for all three alphabets, then NPOSTFIX and NDIRECT, then one context mode per literal block type, then the two context maps, then every prefix code.

Nothing is optional-by-default: if a category has one block type, its switching codes are simply absent; if a context map has one tree, the map is absent. The header pays only for the variety it actually uses — which is why splitting a small file into meta-blocks costs more than it saves.

Header of the stream above

Block splitting

Each of the three alphabets can switch between up to 256 block types mid-meta-block. A switch reads a type symbol (0 = the type before last, 1 = current + 1, else symbol − 2) and a new run length from a 26-symbol count alphabet. The encoder in this page never splits — it declares one type per category — so every switch you see in a trace came from a stream the real library produced.

Uncompressed blocks

Real encoders emit these when a region is incompressible. The decoder pads to a byte boundary and copies MLEN bytes straight through — those bytes still enter the window and can be copied from later.

Padding

After the last meta-block the stream is padded to a byte with zero bits. A stream is therefore not uniquely determined by its content: the same commands can end in different final bytes.

05 — the command alphabet

704 symbols that mean “insert this many, then copy that many”

Insert lengths and copy lengths each have a 24-entry table of base + extra bits: insert 0–5 costs no extra bits, insert 22,594 or more costs 24. The command alphabet is the product of the two, arranged as eleven blocks of an 8×8 grid so that the common combinations land in the low symbols.

The first two blocks — symbols 0–127 — are special: they carry no distance at all and mean “reuse the last distance”. That is why a run of same-distance copies, the signature of columnar or templated data, collapses so hard.

A meta-block ends when MLEN bytes exist. If that happens during a command's literals, the copy the command announced is simply never performed — which is how every stream that does not end in a match ends.

06 — addressing the past

Distances, the cache, and the edge of the window

A distance is coded in one of three regions. Codes 0–15 read the four-entry cache of recent distances, either directly or offset by ±1, ±2, ±3. Codes 16 … 16+NDIRECT are literal distances 1…NDIRECT. Everything above that is a two-part code: a group index picking a number of extra bits, and NPOSTFIX low bits carried in the symbol itself so that distances sharing a residue share a code.

The cache updates on every copy except when the distance came from code 0 — reuse does not reorder the ring. Dictionary references never touch it at all.

The window edge is where Brotli stops being DEFLATE. The largest legal distance at output position p is min(p, 2^WBITS − 16). A distance one past that is not an error: it is dictionary entry zero. Everything above is the dictionary, indexed by distance − max − 1.

07 — literal contexts

Which code a literal is written with

Every literal is coded with a prefix code chosen by the two bytes before it. The two bytes go through a 2,048-byte lookup table — ctx = LUT[mode][p1] | LUT[mode][256 + p2] — producing a context id from 0 to 63. Four modes are available per literal block type:

  • LSB6 / MSB6 — the low or high six bits of the previous byte. Cheap, good for binary and for fixed-width records.
  • UTF8 — a hand-tuned second-order model: sixteen classes for the previous byte (vowel, consonant, digit, space, opening bracket, closing bracket, …) crossed with four for the one before it.
  • SIGNED — tuned for small signed integers, where the sign byte dominates.

Sixty-four contexts do not mean sixty-four prefix codes: a context map folds them onto a smaller set of trees. Choosing that clustering is the encoder's job, and it is the single biggest lever on text.

How a context map is written

The map is NBLTYPESL × 64 tree numbers for literals, and NBLTYPESD × 4 for distances. Three mechanisms shrink it:

  • RLEMAX — one bit, then four more if set. It reserves that many low symbols of the map's own prefix code for runs of zero: symbol k followed by k extra bits means 2^k + extra zeros. Tree numbers are shifted up past the reserved range.
  • Move-to-front — a trailing bit. When set, the values just read are indices into a list of 0…255 that moves each value to the front as it is used, so a map that keeps returning to the same few trees becomes a run of small numbers, which the zero-run codes then eat.
  • Absence — with one tree there is no map at all.

Both maps are read before any prefix code, because the number of trees they mention is exactly how many literal and distance codes follow.

08 — the shared dictionary

122,784 bytes both sides already have

The dictionary is one flat byte array holding 13,504 words, grouped by length: 1,024 four-letter words, then 1,024 of five, 2,048 of six, and so on to 32 words of twenty-four. Word (length L, index i) starts at offset[L] + i·L. A reference names a transformed word: id = transform·2^bits[L] + i, and the copy length field of the command carries L.

The 121 transforms are a prefix string, an operation, and a suffix string. The operations are identity, omit 1–9 from either end, upper-case the first UTF-8 character, or upper-case all of them. So " the ", "The", "time.\n" and "TIME" are all one reference away from the same four-letter word.

The encoder here probes the identity, suffix and upper-case-first families. The decoder implements all 121 — it has to, since it must read whatever a real encoder wrote.

09 — the other direction

Everything the format leaves to the encoder

The specification constrains the decoder completely and the encoder not at all. These are the choices this page makes, in order, with the interim result of each stage from the current input.

Stage 1 — matches

Hash chains over four-byte prefixes, plus a dictionary probe, plus one step of lazy matching. Scored in estimated bits: a match must beat writing the bytes as literals.

Stage 2 — histograms and clustering

Literal counts are collected per context, then the 64 contexts are grouped by Lloyd's algorithm under a cross-entropy cost. More trees code literals better and cost more header.

Stage 3 — codes

Package-merge gives optimal lengths under the 15-bit cap; the writer then picks the simple or complex form per alphabet.

Stage 4 — bits

Where the bytes actually went.

Parameter sweep

The same input encoded under every combination of literal-tree budget and context mode. Nothing here changes what a decoder does; it only changes how many bits the same output costs.
