VueLil / actionable migration / before → after

How to make the generated JavaScript smaller.

This plan does not change Vue algorithms. It changes how exact Vue behavior is expressed in LilScript and how reusable package modules are emitted. Every item below includes the current shape, the target shape, and the compatibility rule that must remain true.

01 / measured non-problem

Do not start by deleting constructor helpers.

Measured

Current pooled helper

function a(){ return new Map }

let first = a()
let second = a()
let third = a()

Forced inline experiment

let first = new Map
let second = new Map
let third = new Map

Inlining all seven constructor helpers saved 65 raw bytes but made gzip 132 bytes and Brotli 104 bytes larger. Brotli already commonalizes repeated constructor text. This family is not responsible for the 25,750-byte gap.

02 / dynamic property access

Keep dynamic access only where it is actually dynamic.

Source migration now

Before: every operation crosses a helper

JsValue classes = hostRead(element, vtcKey);
JS.invoke(classes, "unshift", value);
value = JS.invoke(classes, "join", " ");
hostWrite(element, "className", value);

After: split dynamic and static operations

// Symbol lookup is genuinely dynamic.
JsValue classes = rawElement[vtcKey];

// Known DOM ABI is typed and lowers directly.
classes.unshift(value);
value = classes.join(" ");
element.className = value;

A forced inline of 250 generic reads saved only 67 Brotli bytes. Merely replacing the helper text is not enough. The real win comes when types let the optimizer prove receiver shape, direct call kind, and stable property names.

Guardrail: never turn a truly dynamic user object, getter, or Proxy into a pure typed record. Only internal owned values and declared host interfaces qualify.

03 / internal object representation

Benchmark stable representations; do not assume a class wins.

Decision requires an A/B benchmark

Before: construct fields and closures manually

JsValue refValue = hostCreateObject();
write(refValue, "_rawValue", raw);
write(refValue, "_value", value);
write(refValue, "dep", dep);
hostDefineAccessor(
  refValue,
  "value",
  JS.method0(() => hostRead(refValue, "_value")),
  JS.method1((_, next) => { /* update */ })
);

Candidate A: typed class with shared methods

class RefImpl {
  JsValue rawValue;
  JsValue valueStorage;
  Dep dep;
  bool shallow;

  init(JsValue value, bool shallow) {
    this.rawValue = shallow ? value : toRaw(value);
    this.valueStorage = shallow ? value : toReactive(value);
  }

  JsValue getValue() { /* track, return field */ }
  void setValue(JsValue next) { /* compare, update */ }
}

Candidate B: one shared prototype, plain instances

JsValue refPrototype = createRefPrototype(
  sharedGetValue,
  sharedSetValue
);

JsValue createRef(JsValue value) {
  JsValue ref = Object.create(refPrototype);
  ref["_rawValue"] = value;
  ref["_value"] = value;
  ref["dep"] = newDep();
  return ref;
}

Candidate C: flatten only proven private state

struct Link {
  Effect sub;
  Dep dep;
  int version;
  Link? next;
}

// If Link never escapes, optimization may become:
Effect sub = ...;
Dep dep = ...;
int version = ...;

A JavaScript class is not the goal. The goal is to expose stable shape and shared behavior so the optimizer has options. An escaping public ref cannot be flattened into global locals because identity and multiple simultaneous instances must survive. A private Link may be scalar-replaced completely. A public ref may be smallest as a class or as a plain object inheriting one shared prototype.

Decision gate: implement all viable representations behind the same exact public contract, run the 440 reactivity tests, compare prototypes/descriptors/identity, execute the workload, and choose by final application Brotli. Do not select “class” from source aesthetics.

04 / fixed callable ABI

Remove rest-array trampolines from renderer hot paths.

Language capability needed for 4+ host arguments

Before: wrapper + arguments array + second call

this.patchFn = JS.methodRest((_, args) => {
  state.patchFromArgs(args);
});

void patchFromArgs(JsValue args) {
  JsValue anchor = args.length > 3 ? args[3] : null;
  JsValue parent = args.length > 4 ? args[4] : null;
  // unpack seven more values
  this.patch(n1, n2, container, anchor, parent, ...);
}

After: one fixed-signature callable

this.patchFn = JS.method((
  JsValue self,
  JsValue n1,
  JsValue n2,
  JsValue container,
  JsValue anchor = null,
  JsValue parent = null,
  JsValue suspense = null,
  JsValue namespace = JS.undefined(),
  JsValue scopeIds = null,
  bool optimized = false
) => state.patch(
  n1, n2, container, anchor, parent,
  suspense, namespace, scopeIds, optimized
));

Today LilScript exposes JS.method0 through JS.method3, then JS.methodRest. Renderer callbacks need more arguments, so the port falls into the rest-array path. The required language feature is an arity-inferred host-callable typed closure that preserves this, function identity, name, and length without materializing arguments.

Boundary rule: Teleport and Suspense still receive the dynamic renderer-internals object expected by Vue. Only calls behind that façade become fixed and typed.

05 / function reflection

Make public reflection natural, not a top-level mutation.

Build migration now

Before: mutate every exported function

Object.defineProperty(local, "name", {
  configurable: true,
  value: "createVNode"
});
Object.defineProperty(local, "length", {
  configurable: true,
  value: 0
});
export { local as createVNode };

After: tree-shakable public boundary

// Internal implementation stays mangled.
function a(type, props, children) { /* exact algorithm */ }

// Only this module pays for public reflection.
export function createVNode(type, props, children) {
  return a(type, props, children);
}

The before form is a top-level side effect. A bundler must retain the mutation and often the target function. Removing 52 public name/length mutations saved 1,030 Brotli bytes in the runtime-only ablation. A per-export module lets Vite discard both the wrapper and its implementation when the export is unused.

Do not remove semantic accessors: Object.defineProperty used for actual reactive getters, setters, enumerability, or API descriptors is different. Only post-build public name/length repair belongs in this migration.

06 / tree shaking

Preserve owner modules in the reusable package.

Build migration now

Before: one flattened module

# config/open-world.toml
[bundle]
mode = "single"

# Result
runtime-core.js
  ├─ scheduler
  ├─ renderer
  ├─ hydration
  ├─ compat
  └─ reflection initializers

After: reusable open-world ESM graph

[bundle]
mode = "preserve-modules"

runtime-core/index.js
runtime-core/scheduler.js
runtime-core/renderer.js
runtime-core/hydration.js
runtime-core/compat/*.js

// Vite removes whole unused owners.

The current runtime-only candidate retains 139,699 rendered runtime-core bytes versus Vue's 79,749. Flattening means a top-level effect in one owner can keep unrelated code in the same module. Preserved ESM modules provide robust deletion boundaries even when an optimizer cannot prove individual dynamic operations pure.

Open-world rule: compile one reusable package with all public exports preserved and private names mangled. Do not generate per-scenario export lists. Application-specific removal belongs to Vite.

07 / production graph

False flags must remove imports and initialization.

Source graph selection now

Before: import compat, then branch

import { warnDeprecation, compatConfig } from "./compat";

if (COMPAT) {
  warnDeprecation(...);
}

// compat module initialization already ran

After: production entry excludes the edge

// index.production.lil
import { renderer } from "./renderer";
import { vnode } from "./vnode";
// no compat import when the package format disables compat

export { renderer, vnode, ... };

A false branch does not erase the side effects of a static import. Production graph selection must remove the import edge or prove the imported owner has no side effects. Runtime-only currently retains at least 3.1 KB of compatibility/development string payload before branch code.

08 / implementation order

Migration sequence and acceptance gates.

  1. Reusable package lane. Remove final evidence dependence on VUELIL_PROJECT_EXPORTS. Build one open-world package and consume it in all scenarios.
  2. Preserve modules. Emit owner modules and verify small imports omit unrelated owners.
  3. Production graph cleanup. Remove test, dev, source-map, and disabled compat import edges.
  4. Tree-shakable reflection. Replace namespace-wide mutation loops with per-export boundaries.
  5. Typed reactivity internals. Migrate Ref, ComputedRef, Link, and Dep first; rerun 440 tests and the reactivity benchmark.
  6. Typed renderer callbacks. Add or adopt fixed host-callable arities, then remove *FromArgs trampolines.
  7. Typed DOM ABI. Replace static host reads/writes with extern class members.
  8. Remeasure. Require 234/234 mappings, 216/216 test files, matching scenario checksums, no upstream modules, and canonical Brotli-11.
Success criterion: the final package remains reusable and non-closed-world, all private implementation names are mangled, public Vue reflection stays exact, and downstream Vite removes unused owner modules.
