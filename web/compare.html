Monaco · VS Code’s editor

monaco-editor 0.56, JavaScript versus LilScript.

The JS page is npm monaco-editor. The Lil page is compiled from ports/monaco/entry.lil plus 992 catalog modules. Workers except TypeScript are LilScript; both pages still load Microsoft ts.worker so diagnostics match. The view is a functioning editor — create, type, undo, find, fold, hover, suggest — not a claim that every VS Code workbench feature is present.

Published · not smaller

jQuery 3.7.1 is published. It is not smaller yet.

The public-library row is a pressure test: host-heavy, string keys, a plugin facade. Behavior lanes for core, deferred, data, events, selectors, ajax, and effects are in the repo. The current Brotli-oriented compiler output is larger than npm jquery.min.js. That is stated here so the other cards stay honest.

Parse API

marked 18.0.10, scored without the extension system.

The parse API, GFM and CommonMark HTML, 660/660 against marked@18.0.10. This port has no use(). Official JavaScript is the parse-only 18.0.10 sources, then Oxc and Terser, mangling on and off. The published LilScript artifact is the compiler-selected ESM — not bundled, not post-minified, and still smaller on raw, gzip-9, and Brotli-11 than either minifier, while parsing the same corpus faster in Chromium.
