# Q2 explicit saved search decisions

Optional strict TOML `[decisions] read/write` and CLI `--choices FILE|off` /
`--write-choices [FILE]` now exchange separate raw/gzip/Brotli assignments. The
lock includes typed structural recipe words, output families/sites and the
complete naming plan. Complete current input/configuration/compiler/encoder and
service-limit identities gate reads. Cache settings and lock paths are excluded.
Malformed, oversized, absent and stale documents report misses. Requested write
failures are errors; same-directory atomic replacement preserves the prior file.
Storage is bounded by 1 MiB and one sixteenth of the effective memory ceiling.

A matching assignment is the first terminal move, after structural discovery,
under ordinary walk/work/memory limits. Every recipe uses already proved current
state or current proof producers; canonical equality checks the complete rebuilt
map. Naming and target permissions, exact complete-file scoring, runtime
constraints and per-entry dominance qualify the result. Saved scores/verdicts
are never imported. Effort zero does not replay. New session semantic roots do
not inherit the original input lock. A recipe with publication rewrite lineage
cannot be exported as incomplete words. Complete-build cache hits are disabled
for explicit lock IO; normalization and exact-byte codec reuse still work.

The old M3.9 proposal to carry compression verdicts across matching site/unit
hashes is corrected: other code can change compression, naming and incumbent
comparisons. Only the existing exact-byte/encoder cache can reuse a cost. This
batch deliberately requires full identities and does not claim reuse after
source edits. A lock is an explicit search input, not transparent caching.

[Ten distinct focused checks](focused-tests.json) pass. They cover independent
objectives, exact scores and Node behavior, current module graphs and multi-file
live bindings, stale source/config/limits, hostile assignments and alphabets,
work refusal, bounded IO, failed writes and cleanup, and reconstruction of all
five structural recipe families in a fresh compilation. Existing baseline/effort
and complete-build-cache checks pass. [Release CLI controls](cli-controls.json)
and generated schema agreement pass. No full library/fleet suite was run.

The first full-fixture test encountered a pre-existing parse refusal in the old
integration corpus before replay. Its new focused replacement preserves the
five recipe kinds without depending on that obsolete syntax. The reconstruction
check then found a real replay lifetime defect: fast effort levels did not pin
the baseline, so replacing it could release a later start. Replay now pins that
existing admitted owner through the common walk cleanup. Both reconstruction
and the all-objective round trip pass after the repair. Lower-effort prefix
receipts are omitted when an effort-specific lock changes the walk.
