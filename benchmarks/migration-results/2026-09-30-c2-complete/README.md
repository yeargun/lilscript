# C2 — independent evidence complete

The [pre-registered acceptance](../../../docs/migration/c2-acceptance.md) is
complete. Compiler/oracle source is `4316015c`; measurement tools are
`6b236437`. [Compiler identities](compiler-identity.json) pin all five release
binaries. Production optimizer, effort schedule, codec settings and accepted
size baselines are unchanged by this milestone.

## Independent correctness

- All **30 interpreter tests** pass, including newly modeled struct copies,
  class constructors/inheritance/methods, generic calls, Map/Set identity and
  SameValueZero, and independent UTF-16 strings. The corpus audit exposed and
  fixed the old evaluator's identity/hex/Unicode escape and lone-surrogate
  errors. No expected output was rewritten to follow compiled output.
- [Actual coverage](oracle-coverage.json): **132 of 382 standalone source cases**
  agree byte for byte with the checked-in oracle; **250 are explicitly
  uncovered**, with reasons and declared host-file identities. Host preludes,
  module observers, unsupported effects and module graphs are not mislabeled
  as interpreter coverage. New optimizations need the corresponding independent
  AST or host/observer oracle; this is not a claim of complete interpretation.
- [Case matrix](cases.json): **402 cases × 4 JavaScript lanes**, with **1,571
  passing executions**, **37 existing ledgered case-lanes**, and no unexpected
  failure. Production runs every objective; formation-only runs raw. The
  harvested root-assignment regression passes all four lanes, including raw;
  it is not an outstanding defect.
- [Differential qualification](differential.json): **64 generated functions per
  mask**, seed `0x4a53435f4f524143`, pass eleven portable lanes and five
  JavaScript-record lanes. Portable lanes include native and independently
  compiled C in production, development and formation-only modes. The
  [earlier 32-function seed](differential-first.json) also passes all lanes.
  Three generator unit tests pass. The old fixed record/memory prologue is an
  ordinary conformance case whose `.out` was generated by the interpreter.
- Six public Node tooling tests and nine real-worker Python integration tests
  pass. These check oracle refusal/no-overwrite, coverage loss, host exclusions,
  independent minima, wrong output/counters, input drift, timeouts, controls,
  retained memory, and identity-scoped runtime debts.

## Competitor contracts

[Contracts](bars-manifest.json), [installed-content lock](bars.lock.json),
[results](bars.json) and [replay](bars-replay.json) qualify open ESM, closed
script and script consumer boundaries. **All 27 measured artifacts have
identical hashes on locked replay**: nine independently selected LilScript
artifacts and eighteen eligible competitor artifacts. The same authored oracle
checks the input bundle and every delivered result. Canonical raw/gzip/Brotli,
Brotli-5/gzip-6 robustness, compile wall costs and static inventories are retained.

Terser, SWC, Oxc and Rolldown as separate recipes, esbuild, Closure ADVANCED and
the declared upstream fixture all run in applicable lanes. Closure is explicitly
inapplicable to this runner's open ESM recipe, rather than losing its exports
and setting a false bar. Missing upstream artifacts are likewise inapplicable.
There are no failed eligible recipes in the qualified run. The old
`competitor-recipes.mjs` construction-only receipts can no longer mark a
comparison eligible from export names or raw-size similarity.

These small fixtures qualify the machinery, **not fleet superiority**. Against
the best passing recipe per objective, the consumer fixture is **+9 raw, +5
gzip and −3 Brotli**. Nothing blends that raw/gzip loss into a Brotli win.

Two setup failures are preserved in the work directory: API fixtures were
initially built as closed applications, and a forced Rolldown named-export
setting broke scripts with no exports. The common oracle rejected both.
The final preparation explicitly selects `js-module` for API fixtures, and
Rolldown preserves a script boundary with no synthetic export object. Oxc and
Rolldown's target settings use their pinned APIs rather than ignored options.

## Runtime and carried evidence

[Runtime manifest](runtime-manifest.json), [preparation](preparation.json) and
[all samples](runtime-cost.json) retain **100 fresh-process observations**:
Marked, Zod, PostHog and a generic allocation/call/string workload; five pairs
each, plus three reference identity controls per pair. Every warm-up/sample
passes the same explicit oracle and workload counters. Port candidates are the
compiler-written cores from the qualified C1 port receipt; the generic API is
built by the pinned C2 compiler. The preparation pins upstream source graphs and
the artifact inventory parser.

The predeclared 5% steady-CPU limits are **inconclusive**: control spread is
larger than that precision requirement. Bootstrap intervals, all warm-up and
CPU/wall samples, startup, retained-memory observations and host load remain
visible. [Runtime debts](../../../tests/runtime-evidence.json) bind those four
results to exact artifacts, workload, engine and contract for V1 qualification.
The ledger passes with no unaccounted/stale entries and explicitly reports
`parity_established: false`. No timing result here authorizes a new runtime
regression or proves full-port parity.

MobX's test-path mapping is fixed in its local repository at **`ccccb1d`**;
[the three public Jest tests pass](mobx-mapping.json), with input/artifact hashes
unchanged during testing. Their stale failure entries are removed. The separate
current-compiler MobX build debt remains D3. Zod's exact intermittent upstream
ReDoS-analysis timeout remains an explicitly classified host-dependent check;
its timeout/assertion is unchanged. The quiet-host C1 suite passed all 1,353
tests. Neither this timeout nor an incomplete measurement counts as a win.
