What the data says

Small delivery, honest runtime tradeoffs

Every row measures a delivered production application, not an open-world npm package. Its bundler may tree-shake unreachable exports and minify internal names. SolidLil deliberately uses its closed-world mode, where the application and runtime are optimized together and even unreachable public surface may disappear.

Reading the rankings

One number is not enough

  • Brotli JS is primary because it best represents the JavaScript transferred in a modern production deployment.
  • Page Brotli includes the benchmark HTML and every script requested by the page.
  • CPU uses upstream trace-derived click-to-render duration, with workload-specific warmups and official throttling.
  • Memory is measured after forced major GC using measureUserAgentSpecificMemory().
  • Normalized CPU is the geometric mean of each workload median divided by the fastest median for that workload.

Methodology

Designed to make ordering, warmup, and machine drift visible rather than accidental.

1
Pinned inputs

All 13 requested framework versions come from one immutable upstream commit and their lockfiles.

2
Real browser only

Installed Google Chrome is driven by the upstream Playwright runner. No JSDOM result appears in this report.

3
Randomized complete blocks

Workload and framework order are deterministically shuffled within each of 15 blocks using the recorded seed.

4
Fresh isolation

CPU and memory samples launch isolated browser runs; cold loads use fresh contexts with empty cache.

5
Distribution, not cherry-picks

Tables expose median, p95, mean, sample count, and deterministic bootstrap 95% intervals. Raw samples remain in the checkpoint.
